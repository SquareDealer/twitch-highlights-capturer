# Настройка `config.json`

`config.json` — файл с общими настройками сервиса «Хайлайты Twitch»: пароль, порт, папки, размер буфера, лимиты.
Пороги срабатывания и параметры нарезки настраиваются **не здесь**, а в веб-интерфейсе — см. раздел [«Что настраивается не здесь»](#что-настраивается-не-здесь).

## Быстрый старт

Достаточно такого файла — всё остальное сервис возьмёт по умолчанию:

```json
{
  "port": 8080,
  "password": "придумайте-длинный-пароль",
  "multiStream": false
}
```

Обязательно только поле `password`. Любой ключ можно не писать — тогда действует значение по умолчанию.

**Файла ещё нет?** Создавать его вручную не обязательно. При первом запуске сервис сам создаст файл со случайным паролем из 16 символов и один раз напечатает его:

```
Создан файл конфигурации /config/config.json. Пароль для входа: ...
```

В Docker эта строка видна в логах: `docker compose logs highlights`.

### Где лежит файл

| Как запущен сервис | Где файл | Откуда берётся путь |
|---|---|---|
| Docker | `./config/config.json` рядом с `docker-compose.yml` (внутри контейнера — `/config/config.json`) | переменная `HL_CONFIG` уже задана в образе |
| Без Docker (`npm run service`) | `./config.json` в папке, откуда запускаете | переменная окружения `HL_CONFIG`, если задана |

Папка данных (база, клипы, буфер) задаётся переменной `HL_DATA`: в Docker это `/data` (на сервере — `./data`), без Docker — `./data`.

### Как применить изменения

Файл читается **только при запуске**. После правки перезапустите сервис:

- Docker: `docker compose restart`
- без Docker: остановите сервис (Ctrl+C) и снова выполните `npm run service`

## Общие настройки

Эти ключи читаются из файла при каждом запуске.

### Доступ

| Ключ | Что делает | По умолчанию | Когда менять |
|---|---|---|---|
| `password` | Пароль для входа в веб-интерфейс. Обязателен, пустым быть не может. | случайный, создаётся при первом запуске | Сразу после установки и при любом подозрении, что пароль узнали. |
| `port` | Порт, на котором открывается веб-интерфейс: `http://адрес:8080`. | `8080` | Без Docker — если порт занят. **В Docker не трогайте**: внутри контейнера должен остаться 8080. Внешний порт меняется строкой `HL_PORT=9000` в файле `.env` рядом с `docker-compose.yml`. |

### Папки и программы

| Ключ | Что делает | По умолчанию | Когда менять |
|---|---|---|---|
| `dataDir` | Папка данных: база сервиса, токен Google Drive. | значение `HL_DATA` (`/data` в Docker, `./data` без него) | В Docker — никогда (должно остаться `/data`, проще вообще не писать этот ключ). Без Docker — если данные нужны на другом диске. |
| `libraryDir` | Папка с готовыми клипами. По ней же сервис считает свободное место на диске. | `<dataDir>/library` | Если клипы нужно хранить на другом диске. |
| `bufferDir` | Временная папка с последними минутами записи. **Полностью очищается при каждом запуске.** | `<dataDir>/buffer` | Редко. Это должна быть отдельная папка: не диск целиком, не `dataDir` и не `libraryDir`, и не папка, внутри которой они лежат. |
| `streamlinkPath` | Программа, которая получает эфир с Twitch. Имя или полный путь. | `streamlink` | В Docker не менять. Без Docker — если программа не находится по имени. |
| `ffmpegPath` | Программа, которая режет видео. Имя или полный путь. | `ffmpeg` | То же. |
| `pythonPath` | Python, в котором установлен детектор моментов. | `python` | В Docker не менять. Без Docker — если детектор установлен в отдельное окружение (venv): укажите полный путь, например `.../detector/.venv/bin/python` (Linux) или `.../detector/.venv/Scripts/python.exe` (Windows). |

### Запись и лимиты

| Ключ | Что делает | По умолчанию | Когда менять |
|---|---|---|---|
| `multiStream` | Режим «несколько эфиров». `false` — записывается только один эфир. | `false` | Удобнее переключать в веб-интерфейсе: сервис сам запишет новое значение в файл. |
| `maxStreams` | Сколько эфиров можно записывать одновременно. Работает только при `multiStream: true`. | `5` | Уменьшить на слабом сервере, увеличить на мощном. |
| `bufferSeconds` | Сколько последних секунд каждого эфира хранится на диске. Клип нельзя вырезать из того, что уже выпало из буфера. | `300` (5 минут) | Уменьшить, если мало места. Не ставьте меньше самого длинного клипа с запасом (по умолчанию клип — до 90 секунд). |
| `segmentSeconds` | Длина кусочков, на которые режется запись. | `2` (2 секунды) | Обычно не трогать. |
| `manualClipMs` | Длина клипа, который создаётся кнопкой вручную: последние N миллисекунд эфира. | `60000` (1 минута) | Если ручные клипы нужны короче или длиннее. Не больше `bufferSeconds`. |
| `diskReserveBytes` | Сколько свободного места должно оставаться на диске с клипами. Когда места меньше, сервис удаляет файлы отклонённых клипов; если не помогло — приостанавливает нарезку (запись эфиров продолжается). | `10737418240` (10 ГБ) | Уменьшить на сервере с маленьким диском, иначе нарезка сразу встанет на паузу. |
| `rejectedTtlHours` | Через сколько часов удаляются видеофайлы отклонённых клипов. | `24` (сутки) | Уменьшить, если место кончается быстро. |
| `offlineEndMs` | Сколько ждать возвращения эфира после обрыва. Дольше — эфир считается завершённым, запись останавливается. | `300000` (5 минут) | Увеличить, если стример часто пропадает надолго и возвращается. |

Подсказка по единицам: ключи на `Ms` — миллисекунды (1000 = 1 секунда), на `Seconds` — секунды, `Bytes` — байты (1 ГБ = 1073741824).

### Продвинутые (обычно не трогать)

Эти ключи тоже читаются из файла, а не из профиля. Они лежат внутри блока `detector` (образец — `config.example.json`). Менять их стоит, только если точно понимаете зачем.

| Ключ | Что это | По умолчанию |
|---|---|---|
| `detector.audio.blockMs` | Размер кусочка звука, который анализируется за раз. | `100` (0,1 секунды) |
| `detector.audio.triggerDb` | «Сильный» голосовой всплеск: громче фона на столько децибел. | `15` |
| `detector.audio.triggerVad` | «Сильный» всплеск: уверенность, что это голос, от 0 до 1. | `0.7` |
| `detector.audio.triggerMinMs` | «Сильный» всплеск: не короче. | `500` (0,5 секунды) |
| `detector.chat.repeatShare` | Доля одинаковых сообщений, при которой чат считается «повтором». | `0.6` (60 %) |
| `detector.chat.interactiveWords` | Шаблоны сообщений-голосований («1», «+», «да», «нет»). Такие сообщения не считаются реакцией. | 7 шаблонов |

Шаблоны слов — это регулярные выражения (способ описать «слово с вариациями», например `^ло+л$` = «лол», «лоол»…).

## Что настраивается не здесь

**Пороги и параметры нарезки — в веб-интерфейсе, вкладка «Профили».**

В `config.json` (и в `config.example.json`) есть ключи, которые выглядят как настройки, но после первого запуска **больше не читаются**:

- запасы и длина клипа: `preRollMs`, `preRollLowConfidenceMs`, `postRollMs`, `maxClipMs`, `maxClipsPerHour`;
- пороги срабатывания и оценки: всё в `detector.chat`, `detector.audio`, `detector.events`, `detector.score`, кроме ключей из таблицы «Продвинутые»;
- словари: `detector.chat.laughWords` (смех) и `detector.chat.reactionWords` (реакции).

Как это работает: при самом первом запуске сервис один раз берёт эти значения из файла и создаёт профиль «По умолчанию». Дальше профили живут в базе данных. Сервис сообщает об этом в логах:

```
Создан профиль «По умолчанию» из config.json. Дальше пороги и параметры нарезки правятся в веб-интерфейсе (вкладка «Профили»); эти ключи в config.json больше не читаются.
```

Если вы поменяли порог в файле, перезапустили сервис и ничего не изменилось — это оно. Откройте «Профили» и поменяйте значение там: изменения применяются сразу, без перезапуска.

**Google Drive — на вкладке «Диск».** Ключи Google (Client ID, Client Secret) и папка выгрузки в `config.json` не пишутся.

## Готовые рецепты

### Маленький сервер, мало диска

Один эфир, буфер 3 минуты, резерв 2 ГБ, отклонённые клипы удаляются через 6 часов:

```json
{
  "password": "придумайте-длинный-пароль",
  "multiStream": false,
  "bufferSeconds": 180,
  "diskReserveBytes": 2147483648,
  "rejectedTtlHours": 6
}
```

Резерв подбирайте по диску: примерно 10 % от его размера, но не меньше 1–2 ГБ.

### Несколько эфиров одновременно

```json
{
  "password": "придумайте-длинный-пароль",
  "multiStream": true,
  "maxStreams": 3
}
```

Каждый эфир — это отдельная запись, свой буфер на диске и свой детектор, то есть нагрузка на процессор, память и диск растёт с каждым эфиром. Начните с 2–3 и посмотрите, справляется ли сервер.
При достижении лимита интерфейс покажет: `Достигнут лимит одновременных эфиров (3). Остановите один из эфиров`.

### Смена пароля

1. Откройте `config.json`.
2. Замените значение в кавычках: `"password": "новый-пароль"`.
3. Сохраните файл и перезапустите сервис (`docker compose restart`).
4. Войдите с новым паролем.

Пароль хранится в файле открытым текстом — не выкладывайте `config.json` и не пересылайте его.

## Частые ошибки

Если в файле ошибка, сервис не запускается и пишет в консоль (в Docker — `docker compose logs highlights`) строку, которая начинается с `Не удалось запустить сервис:`.

| Что видите после `Не удалось запустить сервис:` | Причина | Что сделать |
|---|---|---|
| `Не задано поле password: пароль обязателен` | В файле нет `password` или он пустой (`""`). | Добавьте `"password": "ваш-пароль"`. |
| `Неверный тип поля port: ожидается number` | Число написано в кавычках: `"port": "8080"`. | Числа — без кавычек: `"port": 8080`. |
| `Неверный тип поля password: ожидается string` | Пароль из одних цифр написан без кавычек. | Текст — в кавычках: `"password": "123456"`. |
| `Неверный тип поля multiStream: ожидается boolean` | Написано `"true"` в кавычках или `1`. | Только `true` или `false`, без кавычек. |
| `Неверный тип поля detector.chat.interactiveWords: ожидается массив строк` | Вместо списка в `[ ]` указано что-то другое. | Список строк: `["^да+$", "^нет$"]`. |
| `Неверный тип поля detector: ожидается объект` | Вместо блока в `{ }` указано значение. | Блок: `"detector": { ... }`. |
| `Неверное регулярное выражение в поле detector.chat.interactiveWords: ...` | Ошибка в шаблоне слова (например, незакрытая скобка). | Исправьте или уберите шаблон, названный в сообщении. |
| `Папка буфера ... очищается при каждом запуске, а она совпадает с папкой данных (...) или содержит её. Укажите в bufferDir отдельную папку` | `bufferDir` равен `dataDir` или лежит «над» ним. Сервис отказывается стартовать, чтобы не стереть данные. | Укажите отдельную папку, например `/data/buffer`, или удалите ключ `bufferDir`. |
| То же, но `...а она совпадает с папкой клипов (...) или содержит её...` | `bufferDir` равен `libraryDir` или содержит его. | То же. |
| То же, но `...а это корень диска...` | В `bufferDir` указан диск целиком (`/` или `D:/`). | Укажите папку на этом диске. |
| `Expected double-quoted property name in JSON at position ...` | Лишняя запятая после последней строки перед `}`. | Уберите запятую. |
| `Expected ',' or '}' after property value in JSON at position ...` | Пропущена запятая между строками. | Добавьте запятую в конце предыдущей строки. |
| `Bad escaped character in JSON at position ...` | Путь Windows с одинарными `\`: `"D:\data"`. | Пишите `/` или двойной `\\` (см. ниже). |
| `Неверный формат файла конфигурации` | В файле не блок `{ ... }`, а, например, список или просто текст. | Файл должен начинаться с `{` и заканчиваться `}`. |

В сообщениях про JSON сервис указывает строку и столбец (`line 4 column 1`) — ищите ошибку там или строкой выше.

### Пути в Windows

Обратная косая черта в JSON — служебный символ. Правильно так:

```json
{
  "password": "придумайте-длинный-пароль",
  "libraryDir": "D:/clips",
  "pythonPath": "D:\\proj\\detector\\.venv\\Scripts\\python.exe"
}
```

Осторожно: путь вроде `"C:\buffer"` ошибки не даст, но прочитается неправильно (`\b` — служебное сочетание), и папка окажется не той. Всегда используйте `/` или `\\`.

### Ещё три вещи, о которых стоит помнить

- **Опечатка в названии ключа не вызывает ошибку.** Незнакомые ключи просто игнорируются, действует значение по умолчанию. Если настройка «не работает» — проверьте написание (регистр букв важен: `bufferSeconds`, а не `bufferseconds`).
- **Комментарии в JSON запрещены.** Строки с `//` или `#` сломают файл.
- **Изменили файл, а ничего не поменялось?** Либо сервис не перезапущен, либо это ключ профиля — см. [«Что настраивается не здесь»](#что-настраивается-не-здесь).
