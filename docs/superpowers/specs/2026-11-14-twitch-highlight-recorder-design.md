# Twitch Highlight Recorder — спецификация MVP

Источник: исходное ТЗ пользователя от 2026-11-14. **Транскрибация (Whisper, `transcript.json`) вырезана полностью** — все упоминания из ТЗ сняты; клип состоит из двух файлов: MP4 и `markers.json`.

## Конфигурация

| Параметр | Значение |
| --- | --- |
| Платформа | Windows / Electron |
| Просмотр | Официальный Twitch Embed |
| Каналов одновременно | 1 |
| Захват | Streamlink + FFmpeg |
| Буфер | 5 минут |
| Маркеры | 1-9 + комментарий |
| Редактор | React, видеопревью, trim, markers |
| Хранилище | Локальные файлы + SQLite |
| Синхронизация | Google Drive API, автоматическая + ручная |

## Поведение

- Один активный Twitch-канал и один кольцевой видеобуфер.
- `1-9` — создание маркера во время просмотра. Время маркера фиксируется **в момент нажатия цифры**, а не после ввода комментария.
- После цифры появляется небольшое поле комментария поверх плеера, трансляция не останавливается. `Enter` сохраняет маркер, в том числе без текста.
- Цифра сохраняется как `type` маркера. Повторное нажатие той же цифры создаёт новый маркер того же типа.
- Цифры перехватываются только в режиме просмотра приложения и не при вводе текста (комментарий, название клипа). Глобального перехвата цифр нет.
- `F8` — сохранить повтор из буфера в черновик. Несколько F8 — несколько независимых черновиков.
- `F9` — открыть редактор: обрезка видео, перемещение, правка и удаление маркеров.
- `Ctrl+S` — сохранить MP4 и `markers.json`, очистить активный набор маркеров для следующего клипа.
- Маркеры обнуляются только после успешного локального сохранения клипа; Google Drive ждать не нужно. Маркеры, поставленные во время экспорта, попадают в новый рабочий набор и не удаляются при завершении старого экспорта.
- Google Drive синхронизируется в фоне, когда готовы оба файла клипа; плюс ручной запуск синхронизации. Sync Worker не зависит от записи и работает после остановки трансляции.

## Плеер и время

- Просмотр — только официальный Twitch Embed (требование Twitch). Embed требует параметр `parent` и не работает с `file://`.
- Embed и Streamlink получают поток независимо, между ними есть задержка. Embed отдаёт `hlsLatencyBroadcaster`; `getCurrentTime()` для LIVE не поддерживается. Нужен модуль оценки задержки (Time Synchronizer) и ручная корректировка маркеров в редакторе.

## Модель

```ts
type Marker = { id: string; type: 1|2|3|4|5|6|7|8|9; sourceTimeMs: number; comment: string };
type ActiveMoment = { id: string; streamSessionId: string; markers: Marker[]; draftId: string | null };

type CaptureState = "IDLE" | "CONNECTING" | "RECORDING" | "RECONNECTING" | "STOPPING" | "ERROR";
interface CaptureSession { id: string; streamer: string; streamId: string; state: CaptureState; startedAt: string }
interface CaptureSessionManager {
  start(channel: string): Promise<void>;
  stop(): Promise<void>;
  reconnect(): Promise<void>;
  captureReplay(): Promise<string>;
}
```

При обрезке таймкод маркера пересчитывается относительно начала итогового MP4: маркер на `02:10`, начало обрезки `01:40` → в клипе маркер на `00:30`.

## Буфер

| Параметр | Значение |
| --- | --- |
| Размер буфера | 5 минут |
| Целевая длина сегмента | 2 секунды (границы по ключевым кадрам, не точные) |
| Повтор F8 | последние 180 секунд |
| Дозапись после F8 | 5 секунд |
| Очистка | только незакреплённые сегменты |

- Один процесс Streamlink и один FFmpeg, сегменты без перекодирования.
- Маркер может жить дольше 5 минут: при создании маркера закрепляется диапазон сегментов — 30 секунд до и 60 секунд после. Закреплённое не удаляется до сохранения или отмены момента.
- В редакторе закреплённый диапазон можно расширить, пока данные доступны.
- Нужен лимит размера временного хранилища и предупреждение перед удалением несохранённых фрагментов.

## Процессы

- `CaptureSessionManager` в main-процессе запускает и контролирует Streamlink и FFmpeg.
- При недоступности Twitch — состояние `RECONNECTING`, готовые сегменты сохраняются.
- После переподключения — новая временная эпоха сегментов; непрерывность таймкодов не предполагается.

## Файлы и БД

```
TwitchHighlights/
└── streamer_name/
    └── 987654321_2026-11-14_18-30/
        └── 2026-11-14_19-42_funny-reaction_a42f/
            ├── funny-reaction.mp4
            └── markers.json
```

SQLite: `capture_sessions`, `buffer_segments`, `moments`, `markers`, `clips`, `jobs` (экспорт, синхронизация), `drive_files` (Google Drive file ID, версия, статус).
